# 설계 메모

## 구조
- `src/` Spring Boot 백엔드: Doro IAM(OAuth, BFF 세션 쿠키) + Doro Guard(ReBAC) 연동. 독립 DB `service_games`.
- `web/` React + Vite PWA. 게임은 Canvas 로 그리고, 규칙은 화면과 분리된 순수 함수(`engine.ts`)로 둔다.

## 게임 한 개를 추가하는 방법
1. `web/src/games/<slug>/` 에 규칙(`engine.ts`, 테스트 포함)과 Canvas 컴포넌트를 만든다. 컴포넌트는 `GameComponentProps` 규약을 따른다.
2. `web/src/games/registry.ts` 에 slug 로 등록한다.
3. Flyway 마이그레이션(`V{N}__*.sql`)으로 `games` 에 행을 추가한다. 손으로 INSERT 하지 않는다.
4. `application.yaml` 의 `games.scoring.rules.<slug>.max-points-per-second` 를 정한다. 규칙이 없는 게임은 기록을 받지 않는다.

## 점수 신뢰
- 클라이언트가 보낸 점수를 그대로 믿지 않는다. 판은 서버가 발급(`POST /games/{slug}/runs`)하고 시작 시각을 서버가 기록한다.
- 제출 시 `점수 <= 초당 최대 점수 × (서버가 잰 경과 시간 + 네트워크 여유)` 가 아니면 거절한다. 한 판은 한 번만 제출할 수 있고, 거절된 판도 닫힌다.
- 다음 단계: 서버가 시드를 발급하고 입력 로그를 제출받아 같은 규칙으로 재생(replay)해 점수를 재현한다. 엔진이 결정적이라 가능하다.

## 권한
- 목록·랭킹은 공개, 판 시작·점수 제출은 로그인.
- 게임 열기/닫기는 Guard `games_game#manager` 만 할 수 있다(`@DoroGuard`). 코드에 역할 분기를 두지 않는다.

## 귤 폭격 도로롱 (`orange-blitz`)
- **장르**: 세로 화면 슈터. 캐릭터는 좌우로만 움직이고 총알(귤)은 자동으로 나간다. 위에서 적과 **게이트**(+N, ×N, 연사, 공격력, 함정)가 내려온다. 10웨이브마다 보스(근육 도로롱). 끝없이 이어지고 **한 방 컷**이다(귤을 먹으면 보호막으로 한 번 막는다).
- **엔진은 정수만 쓴다**(`web/src/games/orange/engine.ts`). 1px = 100 단위의 정수 좌표, 나눗셈은 내림, 난수는 mulberry32. 부동소수점이 없어서 같은 시드와 입력이면 브라우저든 서버든 같은 결과가 나온다(입력 재생 검증의 전제). 긴 판을 돌려도 모든 수치가 정수인지 테스트가 확인한다.
- **연출은 엔진 밖**: 엔진은 이벤트(`GameEvent`)만 내보내고, 말풍선·파티클·흔들림·개그 대사(`jokes.ts`)는 화면이 맡는다. 연출 난수가 엔진 난수와 섞이지 않는다.
- **균형**: `bot.ts` 의 점검용 봇 두 종류로 잰다(`balance.test.ts`). 숙련 봇과 서툰 봇(늦게 보고, 딴짓하고, 게이트를 가끔 잘못 고름). 둘 다 사람보다 잘해서, 이 봇들이 보스(10, 20, 30웨이브)에서 막히도록 맞췄다 → 사람은 대체로 그보다 일찍 끝난다. 체력은 웨이브마다 `×1.13 + 8` 로 지수 증가하고, 총알 수(16)·공격력(16)에는 상한이 있어서 끝없는 모드도 결국 끝난다. 봇의 10초 구간 최고 점수율은 약 700~1050점/초 → 서버 규칙은 2500점/초.
- **게이트**: 총알은 게이트를 통과하고(적을 가리지 않는다), 지나가며 이로운 쪽 값을 키운다(총알마다 게이트당 한 번, 최대 +8). 한 번 지난 게이트는 사라진다.
