# 설계 메모

## 구조
- `src/` Spring Boot 백엔드: Doro IAM(OAuth, BFF 세션 쿠키) + Doro Guard(ReBAC) 연동. 독립 DB `service_games`.
- `web/` React + Vite PWA. 게임은 Canvas 로 그리고, 규칙은 화면과 분리된 순수 함수(`engine.ts`)로 둔다.

## 게임 한 개를 추가하는 방법
1. `web/src/games/<slug>/` 에 규칙(`engine.ts`, 테스트 포함)과 Canvas 컴포넌트를 만든다. 컴포넌트는 `GameComponentProps` 규약을 따른다.
2. `web/src/games/registry.ts` 에 slug 로 등록한다.
3. Flyway 마이그레이션(`V{N}__*.sql`)으로 `games` 에 행을 추가한다. 손으로 INSERT 하지 않는다.
4. `application.yaml` 의 `games.scoring.rules.<slug>.max-points-per-second` 를 정한다. 규칙이 없는 게임은 기록을 받지 않는다.

## 점수 신뢰
- 클라이언트가 보낸 점수를 그대로 믿지 않는다. 판은 서버가 발급(`POST /games/{slug}/runs`)하고 시작 시각을 서버가 기록한다.
- 제출 시 `점수 <= 초당 최대 점수 × (서버가 잰 경과 시간 + 네트워크 여유)` 가 아니면 거절한다. 한 판은 한 번만 제출할 수 있고, 거절된 판도 닫힌다.
- 다음 단계: 서버가 시드를 발급하고 입력 로그를 제출받아 같은 규칙으로 재생(replay)해 점수를 재현한다. 엔진이 결정적이라 가능하다.

## 권한
- 목록·랭킹은 공개, 판 시작·점수 제출은 로그인.
- 게임 열기/닫기는 Guard `games_game#manager` 만 할 수 있다(`@DoroGuard`). 코드에 역할 분기를 두지 않는다.

## 귤 폭격 도로롱 (`orange-blitz`)
- **장르**: 러너 시점(광고 게임 「라스트 워」 류). 도로롱이 도로를 따라 앞으로 달리며(자동) 귤 탄을 쏘고(자동), 좌우로만 움직인다. 길 위에서 **체력 숫자가 달린 거대 귤 덩어리**, 몰려오는 무리, 게이트(+N, ×N, 연사, 공격력, 함정), 아이템(귤 보호막·치킨·돈다발·별·관통·귤 폭탄)이 다가온다. **내 화력보다 큰 숫자는 비켜 가고, 작은 숫자는 쏴서 부수는 판단**이 핵심이다. 끝없이 달리고 10스테이지마다 보스(근육 도로롱). **한 방 컷**(귤은 보호막으로 한 번 막는다).
- **세계 좌표**: 엔진은 가로 `x` 와 깊이 `z`(도로롱=0, 멀수록 큼)만 안다. 모든 것이 도로롱 쪽(z 감소)으로 다가오고, 원근(멀수록 작게)은 `view.ts` 의 투영이 그리기 때문에 엔진에는 없다. 부딪힘은 가로가 겹치고 깊이도 겹칠 때만 일어난다(이미 지나친 것에는 닿지 않는다).
- **엔진은 정수만 쓴다**(`engine.ts`). 1px = 100 단위의 정수 좌표, 나눗셈은 내림, 난수는 mulberry32. 부동소수점이 없어서 같은 시드와 입력이면 브라우저든 서버든 같은 결과가 나온다(입력 재생 검증의 전제). 긴 판을 돌려도 모든 수치가 정수인지 테스트가 확인한다.
- **숫자 승부의 기준 = 지금 내 실제 화력**: 적의 체력은 스폰되는 순간의 내 화력(`baseFirepower`, 치킨 같은 일시 효과 제외)에서 정한다. 곡선으로 미리 정하면 내 화력이 상한에 막힌 뒤로는 격차만 벌어져서 부술 수 없게 된다(실제로 10스테이지 중반부터 피하기만 하게 됐고, 20스테이지 이후 보스가 죽지 않았다). 귤 덩어리는 "접근하는 약 11초 동안 계속 쏘면 줄 수 있는 피해 × 도전 배율 × 적중 계수 × (60~140%)", 무리는 약 3.5초치, 덩치는 3초치, 보스는 10초치(보스마다 +8%). 도전 배율은 `40% + 스테이지×1%`이고 55% 에서 멈춘다. **적중 계수(32%)가 중요하다**: 이론상 화력 × 시간만큼 피해를 줄 수 있는 게 아니라, 총알이 부채꼴로 퍼져 빗나가고 다른 적도 쏘고 피해야 해서 실제 피해는 훨씬 적다. 계수 없이 도전 배율만 낮췄을 때는 "70% 는 부술 수 있다" 고 계산했는데 실제로는 후반 귤 덩어리의 1% 만 부쉈다(사용자도 "하나도 못 부수고 다 피했다"고 했다). 그래서 **봇이 실제로 부순 비율**로 맞췄다: 초중반 약 76%, 후반(25+) 약 48%(무적 봇 6판 기준). 후반 난이도는 길을 막는 귤 3개, 큰 무리, 빨라지는 속도, 보스 덤벨로 오른다. 화면에는 내 화력(`firepower`)이 보인다.
- **성장이 멈추지 않게**: 총알 수(16)·공격력(40)·연사 간격(최소 5)에는 상한이 있지만, 이미 상한에 닿은 스탯의 게이트는 나오지 않고 공격력 게이트로 바뀐다. 공격력 게이트는 스테이지가 오를수록 커진다(`2 + 스테이지/3`).
- **연출은 엔진 밖**: 엔진은 이벤트(`GameEvent`)만 내보내고, 말풍선·파티클·흔들림·개그 대사(`jokes.ts`)는 화면이 맡는다.
- **균형**: `bot.ts` 의 점검용 봇 두 종류(숙련 / 서툰)와 가만히 서 있는 경우를 `balance.test.ts` 가 잰다. 봇은 사람보다 못하거나 잘하는 부분이 달라서 난이도의 기준이 아니라 **하한(가만히 있으면 일찍 끝남, 스테이지 6 안팎)과 점수 상한의 근거**로만 쓴다. 보스는 무적 봇으로 잡는 시간을 쟀다(스테이지 10~40, 대체로 15~40초). 봇의 10초 구간 최고 점수율은 약 3200점/초(귤 덩어리를 많이 부수면 빨리 쌓인다) → 서버 규칙은 약 3배인 10000점/초.
- **게이트**: 총알은 게이트를 통과하고, 지나가며 이로운 쪽 값을 키운다(총알마다 게이트당 한 번, 최대 +3, 접근하는 내내 겨눠서 쏴야 닿는 정도). 스테이지마다 한 번 나온다.
- **그림**: git 에 두지 않고 MinIO 에서 받는다. [ASSETS.md](ASSETS.md) 참고.
